# ADR-0015: 読み込みは、データルートの外を指しうるパスを、その書き方で拒む

[English](0015-loader-refuses-paths-that-leave-the-data-root.md)

- 状態: 採用

## 文脈

rig のファイルは、ボードとデバイスをデータルートからの相対パスで指し、`load_rig` は各パスを、フロントエンドが渡す読み込み関数に渡す。CLI の読み込み関数はパスをデータルートにつなげてそのまま読んでいたので、rig が `../../x` や絶対パスを書くと、CLI はデータルートの外のファイルを読み、解析エラーは問題の行を標準エラー出力に引用した。rig は他人から受け取ることがあり、計画中の MCP サーバーは LLM が書いた rig を読む。PRD は、同じ入力がどの OS でも Wasm でも同じ結果になることを求めており、Wasm にはパスを解決するファイルシステムがない。

## 決定

- パスは `/` で区切った名前の並びで、どの名前も空・`.`・`..` ではなく、`\` も `:` も含まない。
- `load_rig` は、rig 自身のものも含むすべてのパスを、読み込み関数に渡す前に検査し、規則に反するパスには `LoadError::InvalidPath` を返す。CLI は、ほかの読み込みの失敗と同じく終了コード 2 で終わる。
- データルートの中のシンボリックリンクは、読み込み関数が見つけたとおりに辿る。

## 理由

- コアで検査すれば、CLI、Wasm ビルド、MCP サーバーが一つの規則を共有し、検査を忘れる読み込み関数が生まれない。
- 書き方だけを見る規則は、どの OS でも Wasm でも同じ答えを返し、Unix 上でも Windows のドライブや UNC の形を拒む。
- `\` と `:` を拒むことで、ある OS では無害なパスが、別の OS で絶対パスやドライブになることを防ぐ。

## 採らなかった案

- つなげたパスを `canonicalize` で解決し、データルートで始まるかを確かめる案：ファイルシステムが要るので Wasm では使えず、データルートを用意した人が意図して置いたシンボリックリンクも拒んでしまう。
- CLI の読み込み関数だけで検査する案：後のフロントエンドがそれぞれ同じ検査を持つ必要がある。
