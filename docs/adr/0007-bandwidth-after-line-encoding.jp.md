# ADR-0007: 帯域は回線符号化後のデータレートで表し、デバイスは自分のリンクのレートを要求する

[English](0007-bandwidth-after-line-encoding.md)

- 状態: 採用

## 文脈

Pass 3 と Pass 4 は帯域の値どうしを比べる。トンネルの容量をその背後のリンクと、表示機器の要求帯域を Type-C パイプの残りと、デバイスのリンクを実際に得られるリンクと比べる。PRD の値は 2 種類が混在していた。4K / 60 Hz の表示機器の `bandwidth_requirement_gbps = 12.54` はデータレートである。一方、`max_tunneling_gbps = 32.0` は PCIe Gen3 x4 相当とされていたが、Gen3 x4 は 1 レーンあたり 8 GT/s を 128b/130b 符号化で送るので、運べるデータは約 31.5 Gbps である。USB 3 Gen 1 の `max_gbps = 5.0` は信号レートで、8b/10b 符号化の後に残るのは 4 Gbps である。また PRD は、Pass 4 のレートを GB/s で、出力例を Gbps で書いていた。

PRD の Pass 4 は「各デバイスの要求帯域」に対して警告するとしていたが、要求帯域を書くフィールドはどのデバイスのスキーマにも無かった。出力例は、デバイスの `theoretical_max_gbps` を `actual_gbps` と並べて報告している。

## 決定

- 帯域の値は、データファイルでも出力でも、回線符号化後かつプロトコルのオーバーヘッド（パケットヘッダ、フロー制御など）を引く前のデータレートを Gbps（10⁹ ビット毎秒）で表す。

  | リンク | 信号レート | 符号化 | 書く値 |
  | --- | --- | --- | --- |
  | PCIe Gen3 x4 | 8 GT/s × 4 | 128b/130b | `31.5` |
  | USB 3 Gen 1 | 5 Gbps | 8b/10b | `4.0` |
  | USB4 Gen 3 x2 | 20 Gbps × 2 | 128b/132b | `38.8` |

- PCIe リンクのレートは、エンジンが世代とレーン数から、その世代の符号化方式を使って求める。
- カードと M.2 モジュールは、自分の `[interface]` のリンクのレートを要求する。要求帯域を書く専用のフィールドは設けない。

## 理由

- 表示機器の要求帯域はデータレートなので、容量も同じ形で書けばそのまま比べられる。
- ファイルと出力の単位が同じなら、警告に出た値を元のファイルと突き合わせられる。
- 出力例は、すでにデバイスを自分のリンクのレートと比べている。

## 採らなかった案

- データシートに書かれた公称値: 写しやすいが、リンクが運ぶデータを 128b/130b で 1.5 %、8b/10b で 25 % 多く見積もるので、収まらない表示機器を収まると判定しうる。
- ファイルには公称値を書き、エンジンが換算する: 符号化方式を知るには、すべての値についてプロトコルと世代が必要になるが、`max_tunneling_gbps` はどちらも持たない。
- カードとモジュールに要求帯域のフィールドを設ける: ほとんどのデバイスで `[interface]` の繰り返しになる。

## 結果

データファイルを書く人は、データシートの値をデータレートに換算する。PRD の値は `32.0` を `31.5` に、`5.0` を `4.0` に、`40.0` を `38.8` に改める。
