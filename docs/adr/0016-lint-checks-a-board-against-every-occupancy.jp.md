# ADR-0016: lint はボードの構造を検査し、条件が区別するすべての装着状態で Pass 2 を実行する

[English](0016-lint-checks-a-board-against-every-occupancy.md)

- 状態: 採用

## 文脈

PRD は、ボードだけを静的に解析してレーンの過剰割り当て、循環、届かないソケットを見つける `mblint lint <board.toml>` を求めている。スキーマには、解析では強制されない規則がすでにある。ノードの id は `.` を含まず、`unknown` という id は無く、ルート以外のノードは上流を指し、Mux の mode は切り替えるソケットのすべての状態を覆う。Pass 2 は、一つの装着状態、つまり rig の装着状態について、Mux の mode を選び、ルートのレーン収支を検査する。Mux の条件は一つのソケットを指し、それが空か、装着されているか、あるプロトコルで動くデバイスで装着されているかを調べる。基準ボードの条件ソケットは、それぞれ最大四つである。

## 決定

- `mblint lint [--data-root <dir>] [--json] <board>` は、パスの規則に従ってボードを読み、`mblint check` と同じく終了する。
- lint は、ノードの id、parent、循環、Mux の mode に出てくる名前を検査し、Mux の下にあるのにどの mode からも割り当てられないソケットやブリッジを報告する。
- lint は、ボードの条件が区別するすべての装着状態で Pass 2 を実行し、ある装着状態でどの mode も当てはまらない Mux と、ある装着状態で過剰割り当てになるルートを、それを示す装着状態とともに報告する。
- ルートに届かない連なりは原因の側で報告し、`UnreachableSocket` は Mux が決して割り当てないノードを指す。
- lint の診断はすべてエラーとする。

## 理由

- Pass 2 そのものを実行するので、保証が正確になる。lint を通るボードでは、どの rig も `NoMatchingMode` も `LaneOvercommit` も受けず、通らないボードには、それを受ける rig がある。
- 条件が区別するのは、空、名指すプロトコル、それ以外のプロトコルだけなので、区別ごとに一つの状態で足り、数は条件ソケットの数を指数とする 2 のべき乗程度に収まる。
- ルートに届かないノードは、存在しないか不適切な parent、または循環のために届かない。原因を一度だけ報告すれば、子孫ごとに診断が出ることを避けられる。
- 示す装着状態があれば、ボードの作者は `mblint check` で失敗を再現できる。

## 採らなかった案

- 各 Mux の最大の mode を足し合わせる案：同じソケットに依存する Mux は、すべてが同時に最大の mode をとることはないので、どの rig も過剰割り当てにならないボードを報告してしまう。
- ルートの直下にあるソケットのレーンを数える案：Pass 2 はそれを数えないので、lint が `mblint check` と食い違う。未決事項として残す。
- 装着状態の数に上限を設ける案：これまでに記述したボードは、数が問題になる大きさに遠く及ばない。
- lint を `mblint check` の一部として実行する案：lint はボードの作者が、check は rig の作者が実行する。
