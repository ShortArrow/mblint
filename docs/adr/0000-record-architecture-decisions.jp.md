# ADR-0000: 設計判断を記録する

[English](0000-record-architecture-decisions.md)

- 状態: 採用

## 文脈

スキーマとエンジンについての判断は、それを生んだ会話が失われた後も読める必要がある。また PRD だけでは、その例がなぜその形なのかが分からない。

## 決定

一つの判断を一つのファイル `docs/adr/NNNN-<title>.md` に書き、日本語版 `NNNN-<title>.jp.md` を対にして置く。番号は採用した順に振る。ファイルは次の部分から成る。

| 部分 | 内容 |
| --- | --- |
| 題 | `ADR-NNNN: <判断を一文で>` |
| 状態 | `採用`、または `ADR-NNNN により置き換え` |
| 文脈 | 判断を必要とした事情 |
| 決定 | 何を決めたか |
| 理由 | なぜその案か |
| 採らなかった案 | 退けた案と、その理由 |
| 結果 | 判断から導かれること。何も無ければ省く |

ADR には日付を書かない。いつ採用されたか、その後どう変更されたかは、そのファイルに触れたコミットが記録している。

採用した ADR は書き換えない。それを置き換える判断は新しい ADR とし、古い ADR は状態だけを `ADR-NNNN により置き換え` に変える。

## 理由

- ファイル内の日付は git がすでに記録している情報の重複であり、git と食い違うこともある。
- 採用した ADR を変えずに残せば、判断が置き換えられた後でも、当時何が決まったかを読み手が確かめられる。

## 採らなかった案

- 判断をコミットメッセージにだけ記録する: 話題から探せず、複数のコミットにまたがる判断には一つの置き場所が無い。
