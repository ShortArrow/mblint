# ADR-0008: Pass 3 はトンネルを通るリンクに上限をかけ、Pass 4 は PCIe リンクのレートを世代とレーン数から求める

[English](0008-link-rates-and-tunnel-caps.md)

- 状態: 採用

## 文脈

Pass 4 は、デバイスが実際に得るレートを報告し、それがデバイスの要求するレート（自分の `[interface]` のリンクのレート）を下回るときに警告する。デバイスが得るレートは、挿したソケットによって決まる。PRD のボードではどのソケットも Mux の `allocate` からレーンを受け取るが、M.2 スロットをルートに直結するボードもあり、そのスロットには割り当てが無い。eGPU ボックスの中のカードは、さらにボックスの `max_tunneling_gbps` で制限される。PRD はトンネリングを Pass 3 に置いているが、Pass 3 はまだ無かった。また、Pass 2 のどの診断が後続のパスを止めるかは未規定だった。

## 決定

- Pass 2 の診断はすべてエラーとする。
- Pass 3 は、アダプタの中の各ソケットパスについて、トンネル上限を求める。トンネル上限は、そのパスを囲むアダプタの `max_tunneling_gbps` のうち最小の値とする。そうしたアダプタが無いパスには上限が無い。Pass 3 は今のところ診断を報告しない。
- Pass 4 は、`[interface]` のプロトコルが `pcie` のデバイスについて、リンクのレートを求める。
  - 世代は、デバイスとソケットの小さい方とする。ボードのソケットの世代は、たどり着くルートの世代とする。アダプタの `pcie_slot` は自分の `generation` を持つ。
  - レーン数は、デバイスとソケットの小さい方とする。ボードのソケットのレーン数は、Mux が割り当てたレーン数とし、割り当てが無ければ `max_lanes` とする。アダプタの `pcie_slot` のレーン数は `max_electrical_lanes` とする。
  - レートは、その世代の 1 レーンあたりのデータレートにレーン数を掛けた値とする。トンネル上限があれば、上限まで下げる。
  - 1 レーンあたりのデータレートは、世代 1 から 5 について定める。世代 1 と 2 は 2.0 Gbps と 4.0 Gbps（8b/10b）、世代 3 から 5 は 8、16、32 GT/s × 128/130 とする。
- Pass 4 は、レートがデバイスの要求するレートを下回るときに `Bottleneck` を、ソケットのレーン数が分からないときや世代のレートが定まっていないときに `UnratedLink` を報告する。Pass 4 の診断は警告とする。

## 理由

- それぞれ小さい方を取るのは、PCIe のリンクトレーニングがリンクを決める方法と同じである。
- Mux を通らない M.2 スロットが示すレーン数は `max_lanes` だけである。
- トンネル上限を Pass 3 で求めれば、トンネリングは PRD の位置に置かれたままとなり、表示機器の帯域もそこで差し引ける。
- 遅いリンクをエラーではなく警告とするのは、ボトルネックを `warning` とする PRD の出力例に合う。

## 採らなかった案

- レーン数の分からないソケットは、デバイスの幅で動くとみなす: 配線されたレーンが少ないスロットを見逃す。
- トンネル上限を Pass 4 でかける: 表示機器を扱うまで Pass 3 にすることが無く、扱うようになれば上限の計算を移すことになる。

## 結果

SATA など PCIe 以外のプロトコルのリンクは、レートを求めない。世代 6 のリンクは、データレートを定めるまでレートの分からないリンクとして報告する。
