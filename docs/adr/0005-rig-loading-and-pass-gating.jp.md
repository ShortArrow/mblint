# ADR-0005: rig は呼び出し側が渡す reader で読み込み、失敗したパスより後のパスは実行しない

[English](0005-rig-loading-and-pass-gating.md)

- 状態: 採用

## 文脈

rig はボードとデバイスをパスで指定する。PRD の例は、それらのパスを rig ファイルからではなく、データのルートから書いている（`boards/msi/...`、`devices/cards/...`）。`mblint-core` はネイティブとブラウザ上の Wasm の両方で動く必要があり、ブラウザにはファイルシステムが無く、ファイルはドラッグ & ドロップで渡される。PRD のパイプラインは前のパスに合格したときだけ次のパスへ進むが、実行されなかったパスをどう報告するかは決めていなかった。

## 決定

- rig 内のパスは、データルート（`boards/`、`devices/`、`rigs/` を含むディレクトリ）からの相対パスとする。
- `mblint-core` はファイル I/O を行わない。rig の読み込みには、呼び出し側が渡す reader を使う。reader はデータルートからの相対パスをファイルの内容に対応付ける。CLI はファイルシステムを読み、Web ビルドは渡されたファイルを読む。
- 評価結果は、各パスの結果をパイプラインの順に持つ。あるパスがエラーを報告したら、それより後のパスは実行せず、結果には合格ではなく未実行として記録する。

## 理由

- データルートからの相対パスは PRD の例と一致し、同じデバイスファイルをどの rig からも同じ名前で指せる。
- reader をコアの外に置けば、ネイティブと Wasm のビルドが同じ読み込みコードを使える。
- 「未実行」と「合格」を区別すれば、物理的なエラーのある rig が電気的に問題なく見えることを防げる。

## 採らなかった案

- rig ファイルからの相対パス: rig の置き場所によって、同じデバイスの書き方が rig ごとに変わる。
- 前のエラーにかかわらず全パスを実行する: 割り当てどおりには装着できないデバイスについて後続のパスが推論し、最初の問題から派生した問題まで報告してしまう。
