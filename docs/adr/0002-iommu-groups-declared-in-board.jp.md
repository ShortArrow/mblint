# ADR-0002: IOMMU グループはボード定義に明示宣言する

[English](0002-iommu-groups-declared-in-board.md)

- 状態: 採用
- 日付: 2026-10-27

## 文脈

Pass 4 は、どのデバイスが IOMMU グループを共有しているかを報告する。PRD の初稿はボードに文字列の `iommu_group_hint` しか与えておらず、CLI 出力例にある数値の `group_id = 14` やオンボード SATA コントローラを導けなかった。

## 決定

- ソケットとオンボードコントローラに `iommu_group = <整数>` を書く。値は実機の `/sys/kernel/iommu_groups` で観測したグループ番号とする。
- `ONBOARD_SATA_CONTROLLER` のようなオンボードコントローラは、独立したノード種別 `controller` とする。
- エンジンはグループを推定しない。同じ番号を持つノードを集め、まとめてパススルーしなければならない組として報告する。
- `iommu_group_hint` は廃止する。

## 理由

IOMMU のグループ分けは ACS の対応有無に加え、BIOS / AGESA の版によっても変わるため、トポロジーからの推定は外れうる。観測値を入力にすれば、出力は入力だけで決まる。

## 採らなかった案

- トポロジーと ACS 属性からの推定: 実機なしでボードを書けるが、外れた推定がもっともらしいグループ番号付きで報告されてしまう。
- 宣言値を使い、無ければ推定で補う併用: 推定ロジックの保守が残る。必要になった時点で改めて検討する。

## 結果

`iommu_group` の無いボードでは、Pass 4 は IOMMU 診断を行わない。ボード定義を書くには実機での観測が必要になる。
