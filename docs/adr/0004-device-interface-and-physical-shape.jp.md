# ADR-0004: デバイスはインターフェースと物理形状を分けて宣言する

[English](0004-device-interface-and-physical-shape.md)

- 状態: 採用

## 文脈

Pass 1 は、デバイスがソケットに収まるか、カード同士が覆い合わないかを検査し、Pass 2 は各デバイスが使うプロトコルを必要とする。PRD はアダプタとディスプレイのスキーマを示したが、拡張カードと M.2 モジュールのスキーマは無く、ボードのソケットはどのカテゴリでも物理属性を自由形式のフィールドとして持っていた。

## 決定

デバイスファイルは、何で通信するかを `[interface]` に、何を占有するかを `[physical]` に宣言する。最初に次の 2 種類のデバイスを定義する。

```toml
# devices/cards/<id>.toml
type = "card"

[interface]
protocol = "pcie"
generation = 4
lanes = 16                    # 電気的なレーン数

[physical]
edge = "x16"                  # カードエッジコネクタ: x1, x4, x8, x16
thickness_slots = 3           # 覆うブラケット位置の数。自身の位置を含む
length_mm = 304
```

```toml
# devices/ssds/<id>.toml
type = "m2_module"

[interface]
protocol = "pcie"             # または "sata"
generation = 5
lanes = 4

[physical]
keys = ["M"]                  # モジュールの切り欠き: B、M、またはその両方
form_factor = "2280"
```

ボードのソケットの属性は `category` によって決まり、カテゴリごとに固定の組を持つ。

| `category` | 物理属性 |
| --- | --- |
| `pcie_slot` | `slot_index`、`physical_form_factor`、`open_ended`（既定値 `false`） |
| `m2_slot` | `key`（`B`、`E`、`M`） |
| `sata_port`、`usb_c` | まだ無い |

Pass 1 は次の規則を適用する。

- カードは、エッジがスロットより広くないか、スロットがオープンエンドであれば PCIe スロットに収まる。
- M.2 モジュールは、スロットのキーがモジュールの `keys` に含まれていれば収まる。
- スロット位置 *i* にある厚さ *t* のカードは、位置 *i* から *i* + *t* − 1 までを覆う。スロット位置は CPU から離れる向きに数え、これは ATX でカードのクーラーが張り出す向きである。覆われたスロットにあるデバイスは、塞がれていると報告する。
- PCIe スロット以外のソケットにあるカードと、M.2 スロット以外のソケットにあるモジュールは収まらない。

## 理由

- インターフェースと形状を分けておけば、Pass 1 は `[physical]` だけを、Pass 2 は `[interface]` だけを読めばよい。
- ソケットの属性をカテゴリごとに型付けすると、綴りや置き場所を誤った属性をボードの読み込み時に拒否できる。
- モジュールのキーを列挙すれば、B+M モジュールのために別のキー値を設けずに済む。

## 採らなかった案

- 厚さをミリメートルで持つ: データシートに近いが、すべての検査が、仮定したスロット間隔でスロット位置に換算することになる。
- 省略可能なフィールドを持つ単一のデバイス型: 実在しないフィールドの組み合わせを、すべての検査が扱うことになる。

## 結果

厚さはデバイスファイルの作者が整数のスロット位置数に切り上げて書く。3.5 スロットのカードは `thickness_slots = 4` と書く。各スロット周辺のボード形状をモデル化していないため、`length_mm` と `form_factor` は記録するだけで、まだ検査しない。
