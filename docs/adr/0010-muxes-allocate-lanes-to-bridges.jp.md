# ADR-0010: Mux はソケットだけでなくブリッジにもレーンを割り当てる

[English](0010-muxes-allocate-lanes-to-bridges.md)

- 状態: 採用

## 文脈

MSI MAG X870E TOMAHAWK WIFI では、M2_2 スロットと ASM4242 USB4 コントローラが、CPU からの PCIe 5.0 の 4 レーンを共有する。マニュアルには、M2_2 スロットにデバイスを挿すと両方が PCIe 5.0 x2 で動作すると書かれている。M2_2 が空ならコントローラが 4 レーンすべてを使う。BIOS の設定で M2_2 に 4 レーンすべてを与えると、USB4 のポートは無効になる。Mux の `allocate` はソケットしか指定できず、ブリッジは親から固定の `upstream_lanes` を受け取っていたので、ブリッジが受け取るレーン数をソケットの占有状態に応じて変えられなかった。

## 決定

- mode の `allocate` のキーは、ソケット id またはブリッジ id とする。
- 親が Mux のブリッジは、選ばれた mode が割り当てたレーンを受け取る。親がルートのブリッジは、これまでどおり `upstream_lanes` をルートに要求する。
- BIOS の設定で選ばれる mode は記述しない。ボードのファイルは、BIOS が既定の設定のときのボードを記述する。

## 理由

- Mux はもともと、ソケットが埋まるにつれて消費者の間でレーンが移ることを表している。ブリッジは同じレーンの消費者が一つ増えるだけなので、`allocate` のキーを広げれば新しい仕組みは要らない。
- ルートに届く要求は Mux の `parent` を通したものだけなので、Mux の下のブリッジは Mux を通して一度だけ数えられる。

## 採らなかった案

- ブリッジに専用の `shares_with` フィールドを設ける: Mux がすでに表している切り替えを別の形で書くことになり、パスはそれを別に評価しなければならない。
- BIOS の設定を今モデル化する: rig には BIOS の設定を書く場所が無い。また、構成は誰かが変えるまで既定の設定で動く。
