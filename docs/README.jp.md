# mb-lint

[English](../README.md)

mblint は、PC を組み立てる前に、構成をマザーボードと突き合わせて検証するツールです。ボードを、レーン供給源・Mux・プロトコルブリッジ・ソケットから成る一つの有向グラフとしてモデル化し、カードや周辺機器の組み合わせが実際にどうなるかを報告します。報告するのは、ぶつかるスロット、分割・無効化されるレーン、トンネリングで失われる帯域、そして IOMMU グループを共有しているため単体では VM にパススルーできないデバイスです。

ハードウェアは宣言的な TOML で記述します。同じデータを、人と LLM エージェント向けの CLI と、将来の静的 Web シミュレーターの両方で使います。

## 状況

開発初期で、[ロードマップ](prd.jp.md#8-ロードマップ)の Phase 1 と Phase 2 を終えた段階です。コアライブラリ `mblint-core` は現在、カードと M.2 モジュールがソケットに収まるかと、厚いカードが使用中のスロットを覆わないかの検査、Mux の mode 選択（PCIe bifurcation と M.2 / SATA の排他）、その mode で無効になるソケットに装着されたデバイスの報告、ルートごとのレーン収支の検査ができます。rig を、ボードと、eGPU ボックスのようなアダプタの中に装着したものも含むデバイスとともに読み込み、これらの検査を Pass 1 と Pass 2 として実行します。Pass 3 では、Type-C ポートのモニタが必要な DP Alt Mode のレーンを得られるかを検査し、そのポートの USB データが USB 2.0 に落ちるときは警告します。また、アダプタを通る PCIe リンクにトンネルの上限をかけます。Pass 4 では、各 PCIe デバイスのリンクのレートを求めます。そのレートがデバイス自身のインターフェースのレートを下回るときは警告します。Pass 4 は、挿したデバイスがほかのデバイスやオンボードコントローラと同じ IOMMU グループに入っている場合も報告します。実在のボードをマニュアルから記述した[基準ボード](reference-boards.jp.md)を、テストで評価しています。`mblint check` コマンドは rig を評価し、レポートを人向けに、`--json` を付ければスクリプト向けに出力します。`mblint lint` コマンドは、ボードのファイルだけを検査します。詳しくは[コマンドライン](spec/cli.jp.md)を参照してください。
