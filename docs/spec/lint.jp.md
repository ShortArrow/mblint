# ボードの lint

[English](lint.md)

lint は、rig なしでボードのファイルだけを検査します。lint を通るボードは、[データスキーマ](schema.jp.md)の規則のうち解析では強制されないものを守っており、その上のどの rig も、[解決パス](passes.jp.md)にある Pass 2 の診断 `NoMatchingMode` と `LaneOvercommit` を受けません。

## 構造

すべてのノードの id と parent、すべての Mux の mode に出てくるすべての名前を検査します。

- ノードの id は `.` を含まず、`unknown` でもない。
- `parent` はルート、Mux、ブリッジのいずれかを指す。ただし `usb_c` と `usb_a` のソケットは、代わりに `parent = "unknown"` としてもよい。
- どのノードから `parent` を辿っても、そのノードに戻らない。
- どの mode でも、`when` と `disables` はソケットを指し、`allocate` はその Mux を parent とするソケットとブリッジを指す。
- Mux を parent とするソケットとブリッジは、どれもその Mux の少なくとも一つの mode からレーンを割り当てられる。

上流を辿ってルートに届かないノードは、原因の側で一度だけ報告します。原因とは、存在しないノードを指す parent、レーンを供給できないノードを指す parent、または循環です。

## 装着状態

lint は、ボードの Mux の条件が区別するすべての装着状態について、Pass 2 の mode 選択とレーン収支を実行します。ボードのいずれかの `when` に出てくるソケットを、条件ソケットと呼びます。各条件ソケットは次の状態を、この順にとります。

1. 空。
2. そのソケットのプロトコル条件が名指す各プロトコルで動くデバイスで装着。順は[プロトコル](schema.jp.md#プロトコル)の順。
3. そのソケットのどのプロトコル条件も名指さないプロトコルのうち、同じ順で最初のもので動くデバイスで装着。そのようなプロトコルがあれば。

装着状態は、条件ソケットを id の順に並べた桁を持つ数として順序づけます。最初のソケットが最上位の桁で、各桁はそのソケットの状態を上の順に数えます。

装着状態は、各条件ソケットを `"empty"` か、装着されたデバイスのプロトコルに対応づけるオブジェクトとして書きます。

## 診断

lint の診断はすべてエラーです。

| 診断 | 報告する場合 | フィールド |
| --- | --- | --- |
| `InvalidNodeId` | ノードの id が `.` を含むか、`unknown` である | `node` |
| `UnknownParent` | `parent` がどのノードも指さない | `node`、`parent` |
| `InvalidParent` | `parent` がソケットかコントローラを指す | `node`、`parent` |
| `ParentCycle` | `parent` を辿るとあるノードに戻る | `nodes`：循環。最小の id から始め、`parent` が導く順 |
| `UnknownModeTarget` | mode が、存在しないノードか、そのフィールドが求める種類でないノードを指す | `mux`、`node` |
| `ForeignAllocation` | `allocate` が、別のノードを parent とするソケットかブリッジを指す | `mux`、`node` |
| `UnreachableSocket` | Mux の下のソケットかブリッジが、どの mode からもレーンを割り当てられない | `node` |
| `NoMatchingMode` | ある装着状態で、Mux のどの mode も成り立たない | `mux`、`occupancy`：そのような最初の装着状態 |
| `LaneOvercommit` | ある装着状態で、ルートの需要が供給を超える | `root`、`supplied`、`demanded`、`occupancy`：需要が最大の装着状態。同じならそのうち最初のもの |

診断は種類ごとにこの表の順でまとめ、各まとまりは最初のフィールド、次に二番目のフィールドの順に並べます。Mux とルートは、失敗する装着状態がいくつあっても一度だけ報告します。循環も一度だけ報告します。
