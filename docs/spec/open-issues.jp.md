# PRD v2.0 の未決事項

[English](open-issues.md)

[PRD](../prd.jp.md) のうち、実装前に合意が必要な点。決まった点は `docs/spec/` の仕様書へ移し、この一覧から削除する。

影響の大きい順に並べる。

## スキーマ

| # | 節 | 未決の内容 |
| --- | --- | --- |
| 1 | 4.1 `modes[].when` | `when` は条件を一つだけ持つ。一つの mode に複数の条件を組み合わせる方法は未定。 |
| 12 | 4.3 Rig | ボードのファイルは、BIOS が既定の設定のときを記述する。USB4 コントローラと共有する M.2 スロットのレーンをスロットだけに与えるといった、レーンを動かす BIOS の設定を rig でどう書くかは未定。 |

## 例データの不整合

| # | 節 | 問題 |
| --- | --- | --- |
| 7 | 6.1 JSON | RTX 3060（PCIe Gen4 x16）の `theoretical_max_gbps = 64.0` は、Gen4 x16（約 252 Gbps）とも Gen4 x8 とも一致しない。`PCI_E2` は 4.3 の rig で使われていない。 |

## 振る舞い

| # | 節 | 未決の内容 |
| --- | --- | --- |
| 10 | 4.1 `root_pch_hsio` | `bus = "hsio"` のレーンは PCIe、SATA、USB で共有される。`allocate` 以外に、ソケットが HSIO のレーンをいくつ消費するかを書く方法が無い。 |
| 11 | 4.1 `M2_2.supported_protocols` | M.2 スロットが対応しないプロトコルのモジュール（PCIe 専用スロットの SATA SSD など）を、どのパスで拒否するかが未定。物理的には収まるので、Pass 1 は報告しない。 |
| 13 | 4.1 ルート | チップセットの下のデバイスは、CPU へのリンク（AMD X870E では PCIe 4.0 x4）を共有する。ルートは供給するレーン数を書くが、共有する上りの帯域は書かないので、パスはそのリンクの飽和を検出できない。 |
| 14 | 4.1、4.3 | ボードのレーンは挿す CPU によって変わる。MSI MAG X870E TOMAHAWK WIFI では、Ryzen 8500 や 8300 を挿すと PCI_E1 が PCIe 4.0 x4 で動作し、M2_2 は使えない。ボードのファイルは一つの CPU ファミリーを記述する。rig で CPU をどう指定するかは未定。 |
| 15 | 4.1 `dp_alt_max_lanes` | マニュアルが、Type-C ポートで DisplayPort を出せるとだけ書き、レーン数を書かないことがある。その場合ボードのファイルは `dp_alt_max_lanes` を省き、Pass 3 はそのポートの表示機器を `DpAltModeUnsupported` と報告する。 |
