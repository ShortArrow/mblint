# 解決パス

[English](passes.md)

rig の評価では、パスを順に実行します。あるパスがエラーを報告すると、それ以降のパスは実行しません。結果には、それらのパスを「合格」ではなく「未実行」として記録します。

ファイルは、呼び出し側が渡すリーダーを通して読みます。リーダーは、データルートからの相対パスをファイルの内容に対応付けます。`mblint-core` 自身はファイル I/O を行わないので、CLI と Wasm ビルドは同じ読み込み処理を使います。

## Pass 1: 物理層

Pass 1 の診断はすべてエラーです。

### 収まるかどうか

ボードのソケットにもアダプタのソケットにも、同じ規則を適用します。

| デバイス | 収まるソケット |
| --- | --- |
| `card` | エッジ以上の幅を持つ `pcie_slot`、または奥が開いた `pcie_slot` |
| `m2_module` | キーがモジュールの `keys` に含まれる `m2_slot` |
| `connector = "type_c"` の `adapter` | `usb_c` ソケット |
| `connector = "type_a"` の `adapter` | `usb_a` ソケット |

それ以外の category のソケットに挿したデバイスは、ソケットの種別違いです。ソケットに行き着かないソケットパスは、存在しないソケットです。つまり、id がボードのどのソケットも指さない場合、親のパスにアダプタが無い場合、アダプタにその名前のソケットが無い場合です。

`length_mm` と `form_factor` は検査しません。

### 干渉

スロット位置 *i* にある厚さ *t* のカードは、位置 *i* から *i* + *t* − 1 までを覆います。その範囲にあるボードの別のスロットに挿したデバイスは、干渉を受けます。アダプタのソケットはボード上の位置を持たないので、干渉はボードのスロット同士でだけ検査します。

### 診断

| 診断 | 報告する条件 |
| --- | --- |
| `UnknownSocket` | 割り当てのソケットパスがどのソケットにも行き着かない |
| `WrongSocketCategory` | デバイスがそのソケットの category 用ではない |
| `EdgeTooWide` | カードエッジが、奥の閉じたスロットより幅広い |
| `KeyMismatch` | スロットのキーがモジュールの切り欠きに含まれない |
| `Obstructed` | カードが、別のデバイスを挿したスロットを覆う |

収まるかどうかの診断をソケットパス順に先に並べ、その後に干渉を、干渉を受けたソケットの順に並べます。複数のカードに覆われたスロットは一度だけ報告し、相手はソケット id が最も小さいカードとします。

## Pass 2: 電気的な排他と Mux の解決

### 占有状態

Pass 2 が見るのは、ボードのソケットに割り当てたデバイスです。カードと M.2 モジュールは `[interface]` のプロトコルで、アダプタは上流側のプロトコルで動作するものとします。アダプタの中のデバイスは、ボードのレーンを消費しません。

### mode の選択

各 Mux は、宣言順で最初に `when` が成り立つ mode を選びます。選んだ mode の `allocate` にある各ソケットは、そこに書かれた数のレーンを受け取ります。成り立つ mode が無い Mux は、何も割り当てません。

### レーンの収支

Mux は選んだ mode の `allocate` の合計を、ブリッジは `upstream_lanes` を、それぞれ直接の親に要求します。ソケットがレーンを消費するのは、Mux の `allocate` を通してだけです。要求の合計が `lanes` を超えるルートは、レーン超過です。

### 診断

| 診断 | 報告する条件 |
| --- | --- |
| `NoMatchingMode` | Mux のどの mode も成り立たない |
| `SocketDisabled` | Mux が選んだ mode で無効になるソケットに、デバイスが挿さっている |
| `LaneOvercommit` | ルートへの要求が供給を超える |

診断は種類ごとにこの表の順にまとめ、各まとまりの中はノード id の順に並べます。Pass 2 の診断のうちどれをエラーとするかは未規定です。
